## overview = Обзор

NetAnomalyAnalyzer — программа для анализа сетевых аномалий на Windows. Производит мониторинг и анализ пакетов на сетевых интерфейсах, распознаёт аномальные пакеты по набору правил, журналирует данные в файлы и поддерживает отправку журналов во внешнюю LLM для интеллектуального анализа. Написана на C++17 / Qt 6.

Принцип работы: захват трафика -> правила обнаружения аномалий -> журналы JSONL -> оповещения (звук, системный трей, e-mail) и опционально запросы к LLM.

Если pcap не установлен, программа запускается в демо-режиме с симулятором трафика, включая воспроизведение аномалий — удобно для демонстрации и отладки интерфейса.

Разделы справки: [[build|Сборка и запуск]], [[capture|Захват трафика]], [[packets|Пакеты]], [[anomalies|Аномалии]], [[stats|Статистика и группировка]], [[logs|Просмотр логов]], [[llm|LLM-анализ]], [[notifications|Оповещения]], [[settings|Настройки]], [[service|Служба Windows]].

### Структура проекта

Ядро (захват, правила, статистика, LLM, оповещения) отделено от графической оболочки: одни и те же классы используются GUI-программой NetAnomalyAnalyzer и консольной программой NetAnalyzerService. Автотесты ядра — утилита FilterTest.

## build = Сборка и запуск

### Требования

- Windows 10/11 x64.
- Qt 6.8.x (MinGW 64-bit) и компилятор MinGW из комплекта Qt.
- CMake 3.21+.
- Npcap (для реального захвата; без него работает демо-режим).

### Сборка

Сборка одной командой из каталога проекта:

**powershell -ExecutionPolicy Bypass -File build.ps1**

Скрипт настроит CMake, соберёт цели NetAnomalyAnalyzer (GUI), NetAnalyzerService (консоль/служба), FilterTest (автотесты) и PcapSelfTest (самодиагностика захвата) и запустит автотесты.

Ручная сборка: cmake -B build, затем cmake --build build.

### Проверка

- FilterTest — автотесты фильтров, правил и GUI-моделей; код возврата 0 означает успех.
- PcapSelfTest — проверка pcap: список интерфейсов и короткий захват.

Полезные переменные окружения: NETANALYZER_LLM_URL, NETANALYZER_LLM_MODEL, NETANALYZER_SMTP_TEST=1 (тест почты через локальный тестовый SMTP-сервер в tools/).

## capture = Захват трафика

Кнопки «Старт захвата» и «Стоп» на основной панели управляют процессом захвата. Для каждого выбранного интерфейса выполняется отдельный поток захвата; при остановке потоки корректно завершаются.

На вкладке «Интерфейсы» (раздел «Настройки») выбираются интерфейсы, promiscuous-режим и BPF-фильтр, ограничивающий перехват (например, tcp port 80).

Если библиотека pcap не установлена, при старте включается демо-режим: в поток синтетических пакетов подмешиваются типовые аномалии. Состояние захвата всегда видно в строке состояния внизу окна.

## packets = Пакеты

Вкладка «Пакеты» показывает таблицу перехваченных пакетов: время, интерфейс, протокол, адреса, порты, длину и краткое описание.

- Поле фильтра над таблицей выполняет быстрый текстовый поиск по любой части пакета.
- Кнопка лимита ограничивает число хранимых строк в памяти (память не растёт бесконечно).
- Двойной клик по строке открывает карточку пакета с разбором заголовков по уровням.
- Кнопка «Очистить пакеты» очищает таблицу.

Если в настройках журналирования включена запись пакетов, каждый пакет попадает в журнал packets-ГГГГ-ММ-ДД.jsonl. Этот журнал используется вкладками «Группировка» и «Просмотр логов».

## anomalies = Аномалии

Вкладка «Аномалии» — журнал обнаруженных аномалий: время, тип, серьёзность, описание и ссылки на вовлечённые хосты. Колонка «Обнаружение» показывает, кто выявил аномалию: встроенный анализатор (Net Anomaly Analyzer) или название модели LLM — для находок по итогам анализа журналов.

Реализованные типы правил (пороги и списки настраиваются на вкладке «Правила аномалий»):

- сканирование портов (много портов одного хоста за короткое время);
- SYN-, UDP- и ICMP-флуды;
- broadcast-шторм;
- трафик на подозрительных портах;
- опасные сигнатуры в полезной нагрузке.

Каждая аномалия сразу дописывается в журнал anomalies.jsonl. Контекстное меню строки позволяет отметить аномалию решённой (отметка хранится отдельно и учитывается при оповещениях и в просмотрщике журналов).

## stats = Статистика и группировка

Вкладка «Статистика» ведёт счётчики в реальном времени: пакеты и байты по протоколам, по интерфейсам, по хостам, распределение по времени. Данные берутся из живого потока захвата.

Вкладка «Группировка» строит сводные таблицы поверх журналов packets-*.jsonl: выберите журнал, один-три параметра группировки (например, адрес назначения и порт) и агрегат (число пакетов, байт, среднюю длину). Позволяет быстро оценить, какие узлы генерируют наибольший объём трафика. Источником может служить и текущий поток пакетов (буфер таблицы «Пакеты»). Большие журналы читаются в фоновом режиме: первоначально загружается хвост файла (до 64 МБ / 200 000 записей), а при продолжении записи дозагружаются только новые строки, поэтому окно остаётся отзывчивым.

## logs = Просмотр логов

Вкладка «Просмотр логов» открывает журналы каталога logs (путь задаётся в настройках журналирования):

- anomalies.jsonl — аномалии;
- packets-ГГГГ-ММ-ДД.jsonl — пакеты (если включена запись);
- notifications.jsonl — отправленные оповещения;
- llm-journal.jsonl — обращения к LLM;
- llm-sent.json — отметки об уже отправленных в LLM аномалиях;
- errors.jsonl — ошибки и события подсистем.

Выберите файл в списке, отфильтруйте строки по тексту, включите автопрокрутку для наблюдения за потоком в реальном времени. Для журнала аномалий дополнительно видны статусы «решено».

## llm = LLM-анализ

Программа умеет отправлять журналы во внешнюю LLM (совместимую с OpenAI Chat Completions) для интеллектуального анализа.

- Вкладка «Журнал LLM» показывает историю запросов и ответов: статус, модель, время и текст анализа.
- Кнопка «Анализ LLM» на панели запускает анализ немедленно; в настройках можно включить периодический автоматический анализ.
- Журнал anomalies.jsonl передаётся частями (чанками), чтобы запрос не превышал лимит контекста модели; настройки чанкинга и глубины находятся на вкладке «LLM».
- В контекст попадают только новые аномалии: уже отправленные в анализ записи повторно не передаются (учёт в файле llm-sent.json; отметка ставится после успешного ответа, при ошибке запроса аномалии уйдут в следующий запрос).
- Ответ модели со статусом «warning» или «critical» превращается в аномалию (правило «Анализ LLM»): она появляется в списке аномалий, записывается в anomalies.jsonl и вызывает оповещения по настроенным каналам. Такие записи входят в контекст следующих запросов на общих основаниях (с дедупликацией).

Для настройки укажите адрес сервера (baseUrl), имя модели, таймауты и, при необходимости, ключ доступа. По умолчанию интеграция выключена. Каждое обращение записывается в llm-journal.jsonl, ответы показываются в статус-баре и могут выводиться в трей.

## notifications = Оповещения

NotificationManager отправляет оповещение при срабатывании правила. Доступные каналы:

- статус-бар и системный трей (всегда, при запущенном GUI);
- звуковое предупреждение;
- e-mail через SMTP.

На вкладке «Оповещения» настраиваются SMTP-сервер, адреса получателей, минимальный уровень серьёзности и фильтр по статусу «решено» — уже разобранные аномалии не вызывают повторных оповещений. Журнальный канал notifications.jsonl работает всегда, независимо от остальных.

Для отладки почты в tools/ есть mock_smtp_server.py, поднимающий локальный SMTP на 127.0.0.1:2525.

## settings = Настройки

Вкладка «Настройки» объединяет:

- Интерфейсы — выбор устройств, promiscuous-режим, BPF-фильтр;
- Правила аномалий — пороги, списки портов и подозрительных адресов;
- LLM — адрес и модель, таймауты, чанкинг, автозапуск анализа;
- Оповещения — SMTP, получатели, серьёзность, звук;
- Журналирование — каталог logs, запись пакетов, уровень детализации.

Кнопка «Применить» сохраняет настройки и перечитывает конфигурацию на лету; «Сбросить (перечитать)» возвращает поля к сохранённому состоянию. Настройки хранятся в ini-файле NetAnomalyAnalyzer.ini: в Windows — в общем каталоге данных %ProgramData%\NetAnalyzer\, в Linux — в /etc/netanalyzer/; переопределение каталога — переменная окружения NETAN_CONFIG_DIR.

## service = Консоль и служба Windows

NetAnalyzerService — та же программа без графической оболочки: захват, правила, журналы, оповещения и LLM в консоли или в составе службы Windows.

- NetAnalyzerService — консольный запуск, Ctrl+C останавливает.
- NetAnalyzerService --no-capture — без захвата (только журналы и LLM).
- NetAnalyzerService --run-for N — завершиться через N секунд (для проверок).
- NetAnalyzerService --install / --uninstall — установить или удалить службу (нужны права администратора).

Управление службой: sc start NetAnalyzerService, sc stop NetAnalyzerService, статус: sc query NetAnalyzerService.

## help = Справка

Эта справка открывается по F1 или кнопке «Справка» на основной панели.

- Если в Windows установлен просмотрщик WinHlp32, открывается настоящий файл справки help\netanalyzer.hlp рядом с программой.
- Если просмотрщика нет, используется встроенное окно справки с тем же содержанием: слева закреплено оглавление (прокручивается только текстовая часть), клик по пункту оглавления переводит к соответствующей теме.

Исходник справки — help_src/manual.md; артефакты (netanalyzer.hlp, manual.html, manual_toc.html, manual_body.html) пересобираются скриптом tools/build_help.py.
