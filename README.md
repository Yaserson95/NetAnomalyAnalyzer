# NetAnomalyAnalyzer

Анализатор аномалий в сети: выполняет мониторинг и анализ сетевого трафика,
выявляет аномальные пакеты по набору правил, журналирует их в файлы и
поддерживает отправку журналов во внешнюю LLM для интеллектуального
анализа. Написан на C++17 / Qt 6 с соблюдением принципов ООП —
каждый класс в отдельном файле.

**Документация**: [руководство пользователя](help_src/manual.md) (то же
содержимое встраивается в программу как справка, F1) ·
[архитектура и регламенты для разработчиков](docs/ARCHITECTURE.md).

## Возможности

- **Захват трафика** через Npcap (Windows) / libpcap (Linux, macOS) с поддержкой
  нескольких интерфейсов одновременно — **для каждого интерфейса захват
  выполняется в отдельном потоке**
  (`std::thread` на каждый движок захвата), BPF-фильтров и
  promiscuous-режима. Без установленного pcap собирается демо-режим со
  симулятором трафика (включая воспроизведение аномалий) — удобно для
  демонстрации.
- **Правила обнаружения аномалий** (класс `AnomalyRule`, легко расширяются):
  сканирование портов, SYN-/UDP-/ICMP-флуды, broadcast-шторм,
  трафик на подозрительных портах, опасные сигнатуры в полезной нагрузке.
  Пороги и списки настраиваются в GUI.
- **Журналы**: `anomalies.jsonl`, `packets-*.jsonl` (по желанию),
  `notifications.jsonl`, `llm-journal.jsonl`, `errors.jsonl` — с ротацией по размеру.
- **LLM-анализ**: любой OpenAI-совместимый провайдер (OpenAI, OpenRouter,
  Ollama, LM Studio). Отправка — раз в заданный интервал, по кнопке
  «Анализ LLM» на панели или по кнопке «Отправить сейчас» во вкладке
  «Настройки → LLM» (собирает текущую сводку сети и последние журналы
  аномалий, минуя расписание). Каждое обращение фиксируется в отдельной
  вкладке-журнале (промпт, ответ, статус, длительность). Контекст
  собирается только из новых аномалий: уже отправленные в анализ записи
  повторно не передаются (учёт в файле `llm-sent.json`; отметка ставится
  после успешного ответа, при ошибке запроса аномалии уходят повторно).
  Ответ модели уровня «warning»/«critical» превращается в аномалию
  (правило «Анализ LLM»): она добавляется в список аномалий, пишется
  в `anomalies.jsonl` и вызывает оповещения по настроенным каналам.
  Колонка «Обнаружение» на вкладке «Аномалии» показывает, кто выявил
  запись: анализатор или название модели.
- **Оповещения**: всплывающие окна трей, звук, запись в журнал,
  Telegram-бот, произвольный вебхук (HTTP POST с JSON), электронная
  почта (SMTP, встроенный клиент: SSL/TLS, STARTTLS, AUTH LOGIN) и
  фильтр по статусам: отправляются только выбранные
  уровни (Информация/Предупреждение/Критично) — на всех каналах,
  включая сообщения от LLM; журнал `notifications.jsonl` пишется всегда.
- **Статистика**: сводка по интерфейсам, два графика — пакетов/с и сетевого
  трафика (Кбит/с) по времени, распределение протоколов (все диаграммы
  собственной отрисовкой, без QtCharts).
- **Диалог пакета**: двойной клик по строке в таблице «Пакеты» открывает
  подробную карточку пакета — дерево заголовков Ethernet/IPv4/IPv6/TCP/UDP/
  ICMP/ARP и hex-дамп сырых байтов
  со смещениями и ASCII-колонкой; есть копирование дампа в буфер.
- **Человекочитаемые имена интерфейсов**: везде в GUI (таблицы, статус-бар,
  графики, промпт LLM) отображаются описания вроде «Realtek PCIe GbE Family
  Controller» вместо `\Device\NPF_{GUID}`; полное pcap-имя — во всплывающей
  подсказке и в карточке пакета.
- **Ограничение вывода пакетов**: в таблице хранятся только *n* последних
  пакетов (по умолчанию 300, регулируется спинбоксом над таблицей
  «Показывать последних пакетов»); значение сохраняется в настройках.
- **Фильтрация** (кнопка «Фильтр…» на вкладке «Пакеты» и в «Просмотре
  логов»): отдельный диалог составления условий в формате
  «параметр — действие — значение», например «MAC отправителя |
  начинается на | bc:24». Параметры: MAC/IP отправителя и назначения,
  порты, протокол, интерфейс, длина, информация, флаги TCP (для журналов
  также уровень аномалии, правило, подсистема, сообщение). Действия:
  содержит / не содержит / равно / не равно / начинается на / заканчивается
  на / больше / меньше (числовые поля) / регулярное выражение. Несколько
  условий объединяются по «И». Фильтр пакетов применяется к таблице
  «Пакеты» (буфер при этом продолжает хранить *n* последних пакетов),
  фильтр логов — к записям за выбранный период. Оба фильтра сохраняются
  в настройках между запусками; активный фильтр показывается подписью
  рядом с кнопкой.
- **Сортировка таблиц**: клик по заголовку любой колонки в таблицах
  «Группировка» и «Просмотр логов» сортирует строки (числа — по значению,
  текст — по алфавиту; сравнение ведётся по сырым числам из служебной
  роли ячейки, поэтому значения вида «5.0 МБ» и «100 пакетов»
  сортируются по числовому значению),
  повторный клик по той же колонке меняет направление; строки-ограничители
  «… и ещё N» всегда остаются внизу, выделение группы/записи и панель
  подробностей сохраняются при сортировке, выбранный порядок запоминается
  в настройках между запусками. По умолчанию — по числу пакетов
  (убывание, как в ядре группировки) и по времени записи (возрастание).
- **Группировка** (вкладка «Группировка»): сводка по потоку пакетов,
  сгруппированному по одному-трём параметрам (MAC/IP отправителя и
  назначения, порты, протокол, интерфейс) — например, «кто и сколько
  отправил» (по IP отправителя) или «кто и куда отправлял» (по паре
  IP отправителя + IP назначения). Источник — «текущий поток» (буфер
  таблицы «Пакеты») или выбранный журнал `packets-*.jsonl` за день.
  Таблица групп: число пакетов, байты, средний размер, доли в процентах
  и период наблюдения; нижняя панель — подробная сводка выбранной группы.
  Источник и параметры сохраняются в настройках; таблица автообновляется
  (живой режим — не чаще раза в секунду, журнал — только при изменении
  файла), выделение группы и сводка переживают пересчёт. Большой журнал
  читается в фоновом потоке с хвоста файла (не более 64 МБ / 200 000
  записей за раз), при росте файла дозагружаются только новые записи —
  интерфейс не блокируется даже на многогигабайтных журналах; таблица
  показывает до 5000 групп.
- **Просмотр логов с временной шкалой** (вкладка «Просмотр логов»):
  выбор любого JSONL-журнала, гистограмма событий во времени
  (цвет — по типу/важности события), перетаскиваемый диапазон двумя
  ручками (двойной клик — весь период), таблица записей за выбранный
  период и полное содержимое записи (JSON) в нижней панели.
  Большие файлы читаются с ограничением (хвост до 64 МБ / 200 000 записей,
  таблица — до 5000 строк за раз).
- **Фоновый режим (трей)**: закрытие окна сворачивает приложение в трей —
  захват, детект, оповещения и LLM-расписание продолжают работать;
  восстановление — одиночный/двойной клик по иконке, полный выход —
  пункт «Выход» в меню иконки. Поведение настраивается чекбоксом
  «Сворачивать окно в трей при закрытии» (Настройки → Оповещения,
  по умолчанию включено); при выключенной настройке крестик завершает
  приложение сразу.
- **Настройки**: добавление/удаление перехватываемых интерфейсов, правила,
  LLM, способы оповещения, журналирование.
- **Работа без графической оболочки**: ядро отделено от GUI
  (статическая библиотека `NetAnalyzerCore` — только QtCore/QtNetwork),
  поэтому то же приложение запускается консолью или **службой Windows**
  (`NetAnalyzerService.exe`) на серверах без монитора и иконок. Оболочки
  делят общие настройки и журналы; GUI — лишь один из потребителей ядра.
- **Иконка**: своя иконка приложения (окно, трей, файл `.exe`) —
  генерируется скриптом `tools/make_icon.py`.

## Сборка

Требования: Qt 6 (Widgets, Network), CMake ≥ 3.21, компаньон C++17, для реального
захвата — Npcap SDK.

### Быстрый путь (проверено на этой машине)

Установлено и работает: Python 3.12, `pip install aqtinstall cmake ninja`,
Qt 6.8.3 (`C:\Qt\6.8.3\mingw_64`), MinGW 13.1 (`C:\Qt\Tools\Tools\mingw1310_64`).

```powershell
# один раз установили Qt и компилятор (зеркало задано в tools\aqt_config.ini):
aqt -c tools\aqt_config.ini install-qt -b https://ftp.nluug.nl/languages/qt/ windows desktop 6.8.3 win64_mingw -O C:\Qt --archives qtbase
aqt -c tools\aqt_config.ini install-tool -b https://ftp.nluug.nl/languages/qt/ -O C:\Qt\Tools windows desktop tools_mingw1310

# сборка:
.\build.ps1
.\build\NetAnomalyAnalyzer.exe
```

Важно: каталог `...\mingw1310_64\bin` должен быть в `PATH` при сборке и запуске,
иначе `cc1plus` не найдёт свои DLL (0xC0000135), а приложение — Qt DLL.
`build.ps1` делает это автоматически.

### Реальный захват (Npcap)

Реальный захват включается автоматически, если установлен драйвер Npcap
(есть `System32\wpcap.dll`). CMake ищет pcap в таком порядке:

1. официальный Npcap SDK, если задан `-DNPCAP_SDK_DIR=путь`
   (скачать: https://npcap.com/#download);
2. локальный минимальный SDK в `third_party/npcap` — используется по умолчанию
   на этой машине (сайт npcap.com недоступен из сети). Состоит из заголовка
   `include/pcap.h` с ABI, совместимым с WinPcap/Npcap, и импортной библиотеки
   `lib/libwpcap.a`, сгенерированной из установленной `wpcap.dll`
   утилитами MinGW `gendef` + `dlltool`:

```powershell
cd $env:TEMP
& "C:\Qt\Tools\Tools\mingw1310_64\bin\gendef.exe" "$env:WINDIR\System32\wpcap.dll"
& "C:\Qt\Tools\Tools\mingw1310_64\bin\dlltool.exe" -d wpcap.def `
    -l <проект>\third_party\npcap\lib\libwpcap.a -m i386:x86-64
```

Самодиагностика захвата (входит в сборку, если pcap найден):

```powershell
.\build\PcapSelfTest.exe                     # список реальных интерфейсов
.\build\PcapSelfTest.exe "<устройство>" 5    # тест захвата на 5 секунд
```

Linux:

```bash
sudo apt install qt6-base-dev libpcap-dev   # Debian/Ubuntu
cmake -S . -B build
cmake --build build -j
```

Если pcap не найден, сборка всё равно успешна — приложение запускается
в демонстрационном режиме с симулятором трафика (интерфейс `demo:eth0`,
который намеренно генерирует сканирование портов, SYN-флуд и т.д.).

### Пакетирование (MSI / DEB / RPM)

Пакеты собираются через CPack из готовой сборки; состав задан правилами
`install()` в корневом `CMakeLists.txt`.

**Windows (MSI, CPack + WiX).** Нужен WiX Toolset v3 (`candle`/`light` в
PATH или распакованный в `third_party/wix`):

```powershell
$env:PATH = "C:\Qt\6.8.3\mingw_64\bin;C:\Qt\Tools\Tools\mingw1310_64\bin;$PWD\third_party\wix;$env:PATH"
cmake -S . -B build
cmake --build build -j
cd build; cpack -G WIX
```

Результат: `build\netanomalyanalyzer-1.0.0-win64.msi`. В состав входят оба
exe, Qt DLL с плагинами (xcb-замена — `platforms/qwindows.dll`, TLS —
`schannel`) и рантайм компилятора MinGW (развёртывает `windeployqt`),
`help\netanalyzer.hlp`, README.md и License.txt; ярлыки в меню «Пуск»
(запуск + удаление) и на рабочем столе; установка для всех пользователей.
Npcap НЕ входит в MSI (лицензия) — при отсутствии Npcap приложение
работает в демонстрационном режиме.

**Linux (DEB и RPM, CPack; проверено в WSL Debian 13):**

```bash
sudo apt install qt6-base-dev libpcap-dev cmake ninja-build patchelf rpm
cmake -S . -B build-linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-linux -j
cd build-linux
cpack -G DEB
cpack -G RPM
```

Результат: `build-linux/netanalyzer_1.0.0_amd64.deb` и
`build-linux/netanalyzer-1.0.0-1.x86_64.rpm`. Пакеты самодостаточны:
Qt-библиотеки (Core/Gui/Widgets/Network/DBus/XcbQpa) и плагины входят в
состав, RUNPATH `$ORIGIN` (`patchelf` выставляет `$ORIGIN/..` для плагинов);
системные зависимости (стек X11/xcb, ICU, шрифты) заданы явно.
Также входят desktop-файл, PNG-иконки (генерируются
`tools/make_linux_icons.py`) и симлинки `/usr/bin/netanalyzer` и
`/usr/bin/netanalyzer-service`; каталоги `/etc/netanalyzer` и
`/var/log/netanalyzer` создаёт сам пакет. Смоук-проверка пакета
(установка, ldd, запуск, удаление): `sudo bash tools/linux/verify_packages.sh build-linux`.
RPM собран на Debian и нацелен в основном на Fedora/openSUSE —
на целевой системе проверьте `rpm -i` (или `dnf install`).

## Проверка (что уже прогнано)

- Сборка Qt 6.8.3/MinGW 13.1 — успешно, `build\NetAnomalyAnalyzer.exe` собран.
- Запуск в демо-режиме: поток пакетов идёт, за 2 минуты — 26 аномалий
  (сканирование портов, SYN-флуд, подозрительный порт 4444), записи в
  `logs/anomalies.jsonl` и `logs/notifications.jsonl`.
- **Реальный захват (Npcap, эта машина)**: `PcapSelfTest` перечисляет 10
  интерфейсов, захват на Realtek PCIe GbE за 6 с — 496 пакетов с корректным
  разбором TCP/UDP/ICMP. Приложение с реальным интерфейсом: за ~30 с —
  28397 пакетов (27 МБ), графики статистики и распределение протоколов
  отрисовываются, пакеты (с реальными IP/MAC) пишутся в `packets-*.jsonl`.
- **Имена интерфейсов**: в GUI отображаются описания адаптеров
  («Realtek PCIe GbE Family Controller»), а не pcap-имена.
- **Диалог пакета**: двойной клик по строке таблицы «Пакеты» открывает
  карточку с деревом заголовков и hex-дампом (проверено на реальном
  TCP/HTTPS-пакете: Ethernet/IPv4/TCP-поля и дамп с ASCII-колонкой).
- **График Кбит/с**: второй график на вкладке «Статистика» с историей
  сетевого трафика (проверен на реальном трафике ~1.9 Мбит/с).
- **Кнопка «Отправить сейчас»** (Настройки → LLM): отправляет сводку сети
  и журналы аномалий в LLM мгновенно — проверено против mock-сервера,
  запись в `llm-journal.jsonl` со статусом «Успешно» и источником «Вручную».
- **Авто-деление запроса при превышении бюджета токенов** (Настройки → LLM,
  поле «Бюджит контекста»): если собранный контекст больше бюджета, запрос
  делится на части и отправляется последовательно, а итоговый вердикт
  склеивается (уровень — максимум по частям, находки конкатенируются).
  Оценка размера — символы/4, без токенизатора. Проверено: при бюджете 800
  и контексте ~3200 токенов конвейер отправил 13 частей по ~750 токенов,
  все завершились успешно, итоговый вердикт «Внимание» сходится с одиночным.
- **Лимит строк таблицы пакетов**: по умолчанию 300; под нагрузкой

Примечание: настройки хранятся в ini-файле `NetAnomalyAnalyzer.ini` —
в Windows в общем каталоге данных `%ProgramData%\NetAnalyzer\`, в Linux —
в `/etc/netanalyzer/`; каталоги журналов по умолчанию —
`%ProgramData%\NetAnalyzer\logs` (Windows) и `/var/log/netanalyzer` (Linux).
Каталог конфигурации можно переопределить переменной окружения
`NETAN_CONFIG_DIR` (удобно для тестов и переносных запусков).
QSettings разделяет группу и ключ по символу `/`, поэтому в ini ключ
`interfaces/enabled` — это значение `enabled` в секции `[interfaces]`.
При первом запуске на Windows настройки автоматически переносятся из
старого реестрового хранилища (`HKCU\Software\NetAnalyzer\NetAnomalyAnalyzer`).

## Запуск и использование

1. Вкладка **Настройки → Интерфейсы** — отметьте интерфейсы для захвата,
   при необходимости задайте BPF-фильтр, нажмите «Применить».
2. Кнопка **Старт захвата** на панели — поток пакетов появится на вкладке «Пакеты».
3. Сработавшие аномалии появятся на вкладке «Аномалии», попадут в журнал
   `logs/anomalies.jsonl` и в оповещения.
4. **Вкладка «Статистика»** — сводка и графики загруженности.
5. **LLM**: заполните baseUrl/API-ключ/модель, включите «LLM-анализ» и интервал
   или нажимайте «Анализ LLM». Результаты — на вкладке «Журнал LLM».
6. **Оповещения**: настройте Telegram (токен + ID чата), вебхук или
   электронную почту (SMTP: сервер, порт, шифрование, логин/пароль,
   «От кого»/«Кому»); выберите уровни сообщений (Информация/
   Предупреждение/Критично) — фильтр действует на все каналы и на
   сообщения от LLM; нажмите «Отправить тест» для проверки.

### Запуск без графической оболочки (консоль и служба Windows)

`NetAnalyzerService.exe` использует то же ядро и те же настройки
(тот же ini-файл `%ProgramData%\NetAnalyzer\NetAnomalyAnalyzer.ini`),
поэтому конфигурировать можно через GUI, а работать — без него:

```
NetAnalyzerService.exe                консольный запуск (Ctrl+C — остановка)
NetAnalyzerService.exe --no-capture   без захвата: только журналы и LLM
NetAnalyzerService.exe --run-for 60   завершиться через 60 секунд (проверка)
NetAnalyzerService.exe --help         справка по всем режимам
```

Фоновый режим печатает в консоль события (запуск захвата, аномалии,
статусы каналов оповещений, LLM) и дублирует их в `logs/errors.jsonl`
(`subsystem: service`); при закрытии окна консоли или Ctrl+C корректно
останавливает захват.

Установка службы (требуются права администратора):

```
NetAnalyzerService.exe --install     автозапуск (LocalSystem, без GUI)
sc start NetAnalyzerService          запуск  (или net start NetAnalyzerService)
sc query NetAnalyzerService          статус
sc stop NetAnalyzerService           остановка
NetAnalyzerService.exe --uninstall   удаление службы
```

Служба меняет рабочий каталог на каталог executable, поэтому журналы
пишутся в `logs` рядом с `NetAnalyzerService.exe` (а не в System32).
GUI и службу одновременно запускать не стоит — они делят журналы и
LLM-расписание.

## Примечание о правах

На Windows для захвата требуется установленный драйвер Npcap
(установка с галочкой «API-compatible Mode»), а приложение желательно
запускать с правами администратора. На Linux — запуск от root или
предоставление `CAP_NET_RAW`/`CAP_NET_ADMIN` (`setcap cap_net_raw,cap_net_admin=eip ./NetAnomalyAnalyzer`).
